# Исправление замечаний ревью в GitHub PR
Аргументы команды приходят в конце скилла как `User: …`: номер или ссылка PR заменяет поиск по ветке, остальное – дополнительные указания.

## Ограничения
- С GitHub работать только через GitHub MCP.
- Не коммитить и не пушить: ключ для подписи и авторизации только у меня.
- Отвечать ревьюеру и закрывать тред только по замечаниям, которые исправлены в этом запуске. Остальные треды не трогать: не отвечать, не закрывать, реакции не ставить – с ними разберусь сам.
- Ответ ревьюеру – ровно одно слово `Исправлено`, без пояснений и ссылок.
- Исправлять только то, о чём замечание, код вне его scope не трогать. Соблюдать инструкции репозитория: `AGENTS.md`, `CLAUDE.md` и подобные.

## Поиск PR
- Ветка – `git branch --show-current`, репозиторий `<владелец>/<репо>` – из URL remote, на который настроен upstream ветки, а без upstream – из `origin`.
- Найти открытый PR через `list_pull_requests` с `state: open` и `head: <владелец>:<ветка>`. Если пусто, например PR из форка, – `search_pull_requests` с запросом `is:pr is:open head:<ветка>` и выбрать PR, у которого head-репозиторий совпадает с remote.
- Если PR не найден или подходящих несколько – остановиться и спросить меня.

## Сбор комментариев
- Получить треды через `pull_request_read` с `method: get_review_comments` и `perPage: 100`, пройти все страницы, передавая `endCursor` в `after`.
- Брать все треды, которые не resolved, в том числе outdated. Resolved треды не трогать.
- Читать каждый тред целиком: последующие комментарии могут уточнять или отменять замечание, а мои ответы в треде учитывать как уже принятое решение.
- Для outdated тредов сверять замечание с текущим кодом по `path`, исходным координатам и тексту, потому что код мог сместиться или уже измениться.

## Обработка тредов
Треды обрабатывать по одному, до конца, в таком порядке:
1. Проверить замечание по текущему коду: верно ли оно для этой кодовой базы, не ломает ли существующее поведение, не противоречит ли инструкциям репозитория, другим замечаниям и моим решениям.
2. Если не согласна, замечание уже исправлено до запуска или требует моего решения – в PR ничего не делать и перейти к следующему треду.
3. Если согласна – исправить и проверить правку линтерами и быстрыми проверками для затронутых файлов.
4. Сразу после исправления ответить через `add_reply_to_pull_request_comment`: `commentId` – числовой id первого комментария треда (из якоря `#discussion_r…`, не node ID треда), `pullNumber` – номер PR, `body` – `Исправлено`.
5. Сразу после ответа закрыть тред через `pull_request_review_write` с `method: resolve_thread` и `threadId` – node ID треда вида `PRRT_…`.
Ответы и закрытие не откладывать на конец. Если одна правка закрывает несколько тредов, каждому ответить и каждый закрыть отдельно.

## Итоговая проверка
- Заново получить все треды PR со всеми страницами.
- Каждый исправленный тред должен быть resolved и содержать мой ответ `Исправлено`. Если чего-то нет – доделать и проверить снова.
- Треды, по которым исправлений не было, должны остаться без моих новых ответов и без изменения статуса.

## Отчёт в чате
По каждому открытому треду отдельным пунктом списка, без таблиц:
- ссылка на комментарий, автор и `путь:строка`;
- суть замечания одной строкой;
- решение: исправлено, не согласна, уже было исправлено или нужно моё решение;
- аргументация решения, а для исправленных – что и где изменено.
В конце указать, что изменения не закоммичены и не запушены.
